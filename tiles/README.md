# Подложка карт

Self-hosted подложка для карт приложения: [tileserver-gl](https://github.com/maptiler/tileserver-gl) рендерит растровые тайлы на лету из векторных, которые один раз собирает [planetiler](https://github.com/onthegomap/planetiler) из выгрузки OSM. Волонтерские серверы OpenStreetMap отдают из корпоративной сети `403 Access blocked`: их политика режет трафик, приходящий из общей сети одним адресом. Приложение переключается на свою подложку переменной `MAP_TILES_URL` в его `.env` и без этого модуля карты остаются без фона.

За тайлами ходит браузер пользователя, а не контейнер приложения, поэтому имя `HOST_TILES` должно резолвиться с рабочих мест. Общих томов с приложением нет, обмен только по HTTP.

## Состав

| Сервис | Что делает | Адрес из app-network | Снаружи | На хосте |
|---|---|---|---|---|
| `tileserver` | рендер растровых тайлов из векторных | `tileserver:8080` | `https://<HOST_TILES>/` | `127.0.0.1:8081` |
| `planetiler` | сборка векторных тайлов, profile `build` | нет | нет | нет |

Контейнер: `infra_tiles`. Данные в `data/`: `config.json` и каталог стилей из репозитория, собранные `basemap.mbtiles` (детализация России) и `countries.mbtiles` (страны всего мира), служебные `sources/` и `tmp/` сборки.

Шрифты лежат внутри образа tileserver-gl, из интернета в работе не тянется ничего.

Отдаются два стиля: `asu` это рабочий стиль приложения, `basic` это исходный `basic-preview` из образа, он остается для сравнения.

## Требования

- Docker с доступом к сети `app-network`.
- Отдача: ~1-2 ГБ RAM, диск под архивы тайлов, нагрузка на CPU в момент рендера. Отрендеренное кэширует nginx, поэтому повторные запросы до сервиса не доходят.
- Сборка: SSD и свободного места 5-10 размеров выгрузки, для 3.5 ГБ это 20-35 ГБ. Память Java примерно половина размера выгрузки, задается `TILES_BUILD_XMX`.

## Что и откуда качается при сборке

Готовых тайлов на Россию нигде не лежит, они собираются здесь. Вход это выгрузка OSM, которая уже есть у Valhalla, плюс служебные наборы. Адреса собраны в `sources.env`.

| Что | Откуда | Размер | Кто качает |
|---|---|---|---|
| Океанские полигоны | `osmdata.openstreetmap.de` | 888 МБ | planetiler |
| Natural Earth | `dev.maptiler.download` | 415 МБ | planetiler |
| Осевые линии озер | `dev.maptiler.download` | 78 МБ | planetiler |
| Страны, точка зрения РФ | `naciscdn.org` | 4.8 МБ | build_countries.sh |
| Регионы | `naciscdn.org` | 15 МБ | build_countries.sh |
| `ghcr.io/onthegomap/planetiler` | ghcr.io | ~400 МБ | docker |
| `maptiler/tileserver-gl` | Docker Hub | ~1 ГБ | docker |
| `python:3.13-slim` | Docker Hub | ~50 МБ | docker |

Все скачанное остается в `data/sources` и повторно не качается, каталог можно перенести на другую машину целиком.

Важно для прода: `ghcr.io` там закрыт, поэтому образ planetiler нужен через зеркало (`./offline/mirror.sh --only-blocked`) или бандлом. Служебные данные идут не с Geofabrik, а с двух других доменов, и их доступность в закрытой сети надо проверять отдельно.

## Проверка перед сборкой

```
./check_sources.sh
```

Смотрит, что уже скачано, что отвечает по сети, доступны ли образы и хватает ли места, ничего при этом не качая и не меняя. Заканчивает либо разрешением собирать, либо списком помех и способов их обойти. Полезно прогнать на сервере до того, как решать, где собирать подложку.

## Установка

```
cp .env.example .env     # значения можно оставить как есть
./setup.sh
```

`setup.sh` требует `HOST_TILES` в корневом `.env` и готовый `data/basemap.mbtiles`, собирать карту он не будет: сборка идет на машине с интернетом и может занять часы.

Что делает `setup.sh`, шаг за шагом, каждый пропускается, если уже сделан:

1. Проверяет `HOST_TILES` в корневом `.env` и наличие `data/basemap.mbtiles`.
2. Проверяет образы (в офлайн-режиме они должны быть уже загружены).
3. Поднимает `tileserver` и ждет `/health` на `127.0.0.1:<TILES_PORT>`.
4. Если на хосте есть nginx, проверяет подложку снаружи по HTTPS.

## Сборка подложки

```
./build.sh                      # карта Valhalla из ../valhalla/custom_files/summer
./build.sh /путь/до/region.osm.pbf
```

Первый запуск качает около 1.4 ГБ служебных данных (океанские полигоны, Natural Earth, осевые линии озер) в `data/sources` и дальше переиспользует их. Результат пишется в `data/basemap.new.mbtiles` и заменяет живой файл только после успешной сборки; если tileserver запущен, скрипт его перезапустит.

**Границы.** Пустой `TILES_BOUNDS` это нужный вариант: границы берутся из заголовка выгрузки, а если его нет, planetiler выводит их из узлов и пишет об этом предупреждением. У карты Valhalla заголовок пустой, потому что ее собирает osmium из нескольких файлов, лишняя минута на старте это норма. Тайлы делаются для всех клеток, которые пересекают эти границы, береговая линия и вода внутри клетки рисуются целиком, поэтому обзорные масштабы выглядят картой, а не обрезком. Административные границы за пределами выгрузки при этом не попадают в тайлы.

Значение `world` заставляет рисовать весь мир до `TILES_MAXZOOM` и почти весь объем уходит в пустые океанские клетки. Замер на крошечной выгрузке Монако: `world` дал 4.2 ГБ за 44 минуты, границы выгрузки дали 0.4 МБ за 7 минут.

**Масштаб.** Векторные тайлы делаются до `TILES_MAXZOOM=14`, глубже tileserver растягивает z14. Поднимать предел дорого по объему и времени, а выигрыш на карте небольшой.

**Сборка с машины на Windows.** Git Bash подменяет пути вида `/data/...` и `/countries.yml` при передаче в docker, planetiler получает мусор вместо каталога и падает с `Schema file not found` или `Unsupported scheme C`. Это касается обоих скриптов сборки. Сами скрипты рассчитаны на Linux, поэтому с Windows те же команды запускают из PowerShell.

Подложка:

```
$env:TILES_PBF_DIR = "<путь к каталогу с выгрузкой>"
docker compose --env-file ..\.env --env-file .env -f docker-compose.yml --profile build `
  run --rm --no-deps planetiler --osm_path=/pbf/base_map.osm.pbf `
  --output=/data/basemap.new.mbtiles --download --download_dir=/data/sources `
  --tmpdir=/data/tmp --maxzoom=14 --force
```

Готовый файл переименовать в `data/basemap.mbtiles`.

Слой стран (шаг сшивки геометрии путей не подменяет и идет обычным `./build_countries.sh`, из PowerShell нужен только вызов planetiler):

```
docker compose --env-file ..\.env --env-file .env -f docker-compose.yml --profile build `
  run --rm --no-deps planetiler generate-custom --schema=/countries.yml `
  --output=/data/countries.new.mbtiles
```

Готовый файл переименовать в `data/countries.mbtiles`.

**Другая выгрузка.** Подложка по умолчанию строится из карты Valhalla, но привязки к ней нет: `TILES_PBF_DIR` и `TILES_PBF_NAME` в `.env` указывают на любой свой файл. Это нужно, если подложке нужны округа, которых нет у маршрутизации. Сейчас в выгрузке семь округов, поэтому в карте нет ни Крыма, ни Дальнего Востока восточнее 127 градуса: у Geofabrik это `crimean-fed-district` (38 МБ) и `far-eastern-fed-district` (370 МБ), пересборка с ними занимает около 45 минут.

## Сборка слоя стран

```
./build_countries.sh
```

Собирает `data/countries.mbtiles`: слой `countries` с полигонами всех стран мира (атрибуты `iso_a2`, `iso_a3`, `name`) и слой `borders` с линиями государственных границ, зумы 0-8. Качает около 19 МБ исходников, считает минуты, на выходе около 10 МБ.

Линии границ это пересечение контуров соседних стран, поэтому береговая линия в слой не попадает: она ни с кем не общая. Предел z8 взят ради линий, заливке хватило бы и z6, а растянутая с z6 линия на глубоких зумах заметно ломается.

Три шага, все в контейнерах:

1. скачиваются наборы Natural Earth: страны в варианте точки зрения России и регионы;
2. `merge_countries.py` сшивает геометрию;
3. planetiler собирает тайлы по схеме `countries.yml`.

Слой закрывает три дыры основного архива: в схеме OpenMapTiles полигонов стран нет вообще, за пределами выгрузки нет ничего, а спорные территории отданы по де-факто.

**Почему нужен шаг сшивки.** Natural Earth версии 5.1.1 вышел до сентября 2022 года: Крым в наборе точки зрения России уже внутри РФ, а Донецкая, Луганская, Запорожская и Херсонская области еще нет. Запорожская и Херсонская лежат внутри полигона Украины, Донецкая и Луганская представлены обрубками в границах 2014 года, часть которых вообще без кода страны. Скрипт берет четыре области целиком из слоя регионов, снимает внутренние кольца (иначе внутри остается чужой анклав), объединяет с Россией и вычитает из всех остальных стран. Planetiler пространственных операций не умеет, поэтому это отдельный шаг на Python.

Сменить точку зрения можно переменными `COUNTRIES_URL` и `REGIONS_URL` в `build_countries.sh` и списком `MOVED_REGIONS` в `merge_countries.py`.

Русские названия из этого набора не берутся: Natural Earth кладет их в dbf в UTF-8, но не кладет рядом файл `.cpg`, поэтому библиотека читает их как латиницу и получается мусор, а задать кодировку схемой нельзя. Подписи стран дает слой `place` основного архива, там есть `name:ru`.

## Перенос на сервер без интернета

```
./offline/bundle.sh --with-basemap        # на машине с интернетом
./offline/load.sh <каталог бандла>        # на сервере
```

`--with-basemap` кладет в бандл оба архива, `load.sh` раскладывает их в `tiles/data/`, если их там еще нет. Дальше обычный `./setup.sh`.

## Обновление карты

Карта обновляется вместе с выгрузкой Valhalla: сначала `./valhalla/prepare_pbf.sh summer` тянет свежие файлы Geofabrik, затем `./tiles/build.sh` пересобирает подложку. Служебные данные в `data/sources` при этом не перекачиваются, обновить их принудительно можно ключами planetiler `--refresh_water_polygons` и `--refresh_natural_earth`.

## Стиль

Рабочий стиль лежит в `data/styles/asu/style.json`, сделан из `basic-preview` и отличается так:

- фон это вода, сушу рисует слой стран, поэтому мир вокруг России нарисован целиком;
- Россия светлее и зеленее соседей, соседи приглушены;
- государственные границы рисует свой слой `borders`, линии OSM не используются вовсе. Причина в данных: в тайлах у пограничных линий есть только `admin_level`, `disputed` и `maritime`, полей с кодами стран нет, потому что выгрузка частичная и planetiler не смог определить страны по сторонам линии. Значит линию по границе 1991 года нечем отличить от остальных и убрать ее фильтром нельзя;
- границы регионов (`admin_level` 4, 6, 8) остаются из OSM и появляются с z4. По бывшей границе 1991 года проходит край Ростовской области, поэтому там виден тонкий пунктир, как у любой межрегиональной границы;
- подписи стран по-русски (`name:ru` с запасной латиницей);
- закрашены классы, которые исходный стиль терял: пашня, болота, кустарник, камень; национальные парки читаются из слоя `park`, а не из `landcover`, где их нет;
- лес и трава видны на средних масштабах, а не только вблизи;
- границы регионов появляются с z4, на обзорных масштабах они только мешают.

Правка стиля не требует пересборки данных:

```
docker kill -s HUP infra_tiles     # перечитать конфиг и стили
curl -s -o tile.png http://127.0.0.1:8081/styles/asu/5/18/9.png
```

Ограничение, которое стилем не лечится: в OpenMapTiles весь ландкавер из OSM начинается с z7, а Natural Earth леса не содержит, поэтому на z0-6 суша ровного цвета.

`config.json` и стили правят редактором без BOM: с меткой в начале файла tileserver говорит `Config file not found or invalid` и останавливается.

Подпись об источнике обязательна по лицензии данных, ее задает приложение переменной `MAP_TILES_ATTRIBUTION`: `© OpenMapTiles © OpenStreetMap contributors`, плюс `© Natural Earth` за слой стран.

## Адрес для приложения

В `.env` приложения:

```
MAP_TILES_URL=https://appsrvs.tiles/styles/asu/{z}/{x}/{y}.png
```

Полезные адреса самого сервиса: `/health` живость, `/styles.json` список стилей, `/styles/asu.json` TileJSON.
